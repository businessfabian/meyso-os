## Cross-Project Prioritaet

### meyso-website: Dein Aushaengeschild - hoechster ROI pro Quick Win

meyso.de ist der erste Eindruck fuer jeden potenziellen Kunden. Die Site hat bereits die stärkste Animations-Schicht im Portfolio (Aurora, TiltCard, CursorTracker, Parallax), aber zwei strukturelle Luecken:

1. **Kein Dark Mode**: Jeder Tech-affine User der abends auf dem Laptop schaut, sieht ein blendendes Weiss. Das konterkariert den "moderner Developer"-Eindruck
2. **Keine CSS Custom Properties**: Alle Colors sind hardcoded. Dark Mode ist ohne dieses Fundament nicht machbar

Quick Wins hier haben den groessten Marketing-Impact, weil jeder Hirmax-Kunde, jeder toolradar-User und jeder Villa-Nina-Gast auch auf meyso.de landet.

### villa-nina-sardinia: Groesstes Upgrade-Potenzial weil noch in Entwicklung

Note 4.5/5 heisst: das Design-System ist bereits auf Spitzen-Niveau. Aber das Projekt hat einen Pre-Launch-Blocker: **die mobile Navigation fehlt komplett**. Auf Mobile sieht der User keine Navigationspunkte. Das ist kein UX-Problem, das ist ein Blocker.

Daneben: Villa Nina hat das beste Component-System im Portfolio (Button mit Sweep-Fill, Input mit Floating Label, Grain-Overlay). Das sollte als Basis fuer das KMU-Template betrachtet werden.

### toolradar: Accessibility-Schulden als groesstes Risiko

ToolRadar ist in Phase 1 (Distribution-Focus). Die kritischste Luecke ist nicht visuell sondern legal: `ContactForm.tsx` hat Input-Felder ohne Labels. Das ist ein WCAG-Failure. Wenn ToolRadar wächst und Enterprise-Kunden anspricht, kann fehlende Accessibility zum Problem werden.

UI-seitig ist die Chance der Framer-Motion-Integration: die Discovery-Experience sollte sich lebendig anfuehlen.

### hirmax-scheibenbilder: Funktion vor Aesthetik, aber Safety-Checks notwendig

Live-Portal mit echten Bestellungen. Note 2.7/5 klingt niedrig, aber es funktioniert: Kunden bestellen, Rabatte werden berechnet, Max Hirt verwaltet im Admin. Die UI-Probleme sind real aber nicht geschaeftskritisch.

**Ausnahme:** Der fehlende Loading-State auf dem Submit-Button ist ein echter UX-Bug. User koennen Doppel-Submits ausloesen. Das sollte der erste Fix sein.

## "Diese Woche" Empfehlung

Wenn ich Dave waere und 3 Tasks aus allen 4 Projekten naechste Woche angehen wuerde:

### Task 1: villa-nina-sardinia - Mobile Navigation (2h)

**Warum zuerst:** Das ist ein Blocker fuer den Launch. Ohne mobile Navigation ist das Projekt nicht live-faehig. Kein anderer Quick Win hat den gleichen Unblocking-Wert.

**Was tun:** `HeaderClient.tsx` als Client-Island erstellen. Hamburger-Button + Drawer. `motion.div` Slide-in von rechts. Locale-Switcher integrieren. Focus-Trap mit `focus-trap-react` oder manuell.

**Dateien:** `components/layout/Header.tsx`, neu: `components/layout/HeaderClient.tsx`

---

### Task 2: hirmax-scheibenbilder - Submit-Button Loading-State (15 Min)

**Warum zweitens:** Das einzige Problem in Hirmax das aktive Schaeden anrichten kann (Doppel-Bestellungen). Schnellster Fix mit hoechstem Safety-Impact.

**Was tun:** `Loader2` Icon aus Lucide, `animate-spin` Klasse, `disabled={isSubmitting}` auf Submit-Button in `BestellFormular.tsx`.

**Datei:** `modules/produkte/BestellFormular.tsx`

---

### Task 3: toolradar - ContactForm Labels + FAQ ARIA (20 Min)

**Warum drittens:** Beide Accessibility-Fixes zusammen in einem Commit. Kein visueller Impact, aber rechtliche und ethische Sauberkeit. Wenn ToolRadar waechst, sollte das Fundament stimmen.

**Was tun:** `<label htmlFor="...">` auf alle ContactForm-Inputs. `aria-expanded`, `aria-controls`, `id` auf FAQ-Accordion.

**Dateien:** `components/ContactForm.tsx`, `components/FaqAccordion.tsx`

## "Diesen Monat" Empfehlung (Bigger Moves)

### Prioritaet 1: meyso-website - CSS Custom Properties + Dark Mode (2-3h)

**Strategische Begruendung:** Alle anderen Bigger Moves in meyso-website (Radix UI, Testimonials, Skeleton) sind sekundaer. CSS Custom Properties sind das Fundament. Dark Mode ist der Output den Nutzer sehen. Beides zusammen macht aus meyso.de ein 2026-taugliches Aushängeschild.

**Risiko:** Medium. Viele Dateien berührt. Empfehlung: Feature-Branch, vollständig testen vor Merge.

### Prioritaet 2: villa-nina-sardinia - Parallax-Hero + Booking-Micro-Animations (2-3h)

**Strategische Begruendung:** Villa Nina hat das beste Design-System im Portfolio. Mit Parallax und Booking-Animations wird aus einem guten Design-System eine Buchungs-Experience die Urlaubsgefuehle weckt. Direkt konversionsrelevant.

**Risiko:** Low (additiv, kein bestehender Code berührt).

### Prioritaet 3: toolradar - Tool-Card Redesign (2h)

**Strategische Begruendung:** ToolCard ist das am häufigsten gerenderete Element auf ToolRadar. Eine bessere Card = besseres Gesamt-Erscheinungsbild. Im Kontext von Phase 1 (Distribution) ist ein polisherter erste Eindruck bei organischem Traffic wertvoll.

**Risiko:** Low (isolierte Komponente).

## Shared Design System Hinweise

### Pattern 1: Floating Labels und Editorial Inputs

Villa Nina hat `Input.tsx` mit Floating-Label, Bottom-Hairline-Only, Terracotta-Underline on Focus. Das ist das beste Form-Design im Portfolio. Das gleiche Pattern sollte in das `meyso-kmu-template` eingebaut werden und koennte als `FormInput` Component in neuen Client-Projekten standardisiert werden.

**Aktuell:** hirmax-scheibenbilder und meyso-website haben Standard-Input-Felder ohne Floating Label.

### Pattern 2: Scroll-Reveal-System

meyso-website hat `Reveal.tsx` (Fade-Up via IntersectionObserver). ToolRadar hat `.reveal` CSS-Klassen. Villa Nina hat `FadeUp.tsx` (Framer Motion). Hirmax hat nichts Systematisches.

**Empfehlung:** Ein einziges `FadeUp` Pattern fuer alle Projekte. Framer-Motion-basiert (villa-nina Version) mit `useReducedMotion()` Support. Als Utility in `meyso-kmu-template` standardisieren.

### Pattern 3: CSS Custom Properties via `@theme` (Tailwind v4)

Villa Nina und ToolRadar nutzen Tailwind v4 mit `@theme` in globals.css. meyso-website und hirmax nutzen Tailwind v3 mit `tailwind.config.ts`.

**Empfehlung:** Bei naechstem grossem Refactor oder neuem Projekt: Tailwind v4 + `@theme` als Standard setzen. Villa Ninas `@theme` Struktur ist ein Referenz-Implementation fuer das KMU-Template.

### Pattern 4: Button mit Sweep-Fill Animation

Villa Ninas `Button.tsx` (`translate-x-full -> translate-x-0` Fill in 500ms) ist technisch eleganter und visuell auffälliger als die Standard `hover:bg-change` Patterns in den anderen Projekten. Kandidat fuer KMU-Template-Standardisierung.

### Pattern 5: Inline SVG Logo als React Component

Villa Nina hat `Logo.tsx` als React-Komponente die CSS-Variablen fuer Fonts erbt. Kein `<img src="logo.svg">`. Das ermöglicht Brand-Color-Theming ohne separate Assets. Best Practice die in anderen Projekten übernommen werden sollte.
